# 子代理

子代理允许您将专注的任务交给一个在其独立上下文中运行的代理。当您想保持主对话精简、同时运行独立的研究轨道，或将专业代理链接成流水线时，可以使用它们。主代理最多可以同时生成四个子代理，使用 Ctrl+G 实时监控它们，并在它们完成时合并结果。

## 核心能力

- **自主执行** - 子代理在自己的上下文中独立运行，自主程度取决于代理配置
- **实时进度跟踪** - 查看子代理工作时的实时状态，包括当前工具调用和活动
- **并行和顺序执行** - 同时运行最多四个子代理，或使用任务图通过依赖关系链接它们
- **专用执行监控器** - 在专注面板中检查每个子代理的活动，不打断主聊天
- **细粒度权限控制** - 使用工具级别和批准级别设置来限定每个子代理的权限
- **结果聚合** - 每个子代理完成时自动将摘要返回给主代理

## 选择代理

默认情况下，子代理使用 Kiro 内置的默认代理配置生成，该配置处理通用任务。要使用自定义代理，请在分配任务时按名称引用它:

```bash
> 使用 backend 代理重构支付模块
```

子代理从其使用的代理配置继承工具访问权限、`toolsSettings` 和 `allowedTools`。

**自定义编排代理需要子代理工具**

如果您正在构建会生成子代理的自定义代理，请在它的 `tools` 数组中包含 `subagent`（或通过 `@builtin` 符号添加）。没有它，代理无法委托任务。

## 子代理如何工作

1. **任务分配** - 您描述一个任务，主代理决定是否委托它
2. **子代理初始化** - 根据代理配置创建具有自己上下文和工具访问权限的子代理
3. **自主执行** - 子代理完成任务，仅在工具需要时暂停等待批准
4. **进度更新** - 您在主聊天中看到实时进度，可以在执行监控器中查看详情
5. **结果返回** - 完成后，子代理调用内置的 `summary` 工具并将发现返回给主代理

## 工具可用性

默认子代理拥有与默认主代理相同的内置工具。没有特定于子代理的允许列表或拒绝列表。当您委托给默认子代理时，它可以使用 `read`、`write`、`shell`、`aws`、`grep`、`glob`、`code`、`web_search`、`web_fetch`、`introspect`、`knowledge`、`thinking`、`todo`、`tool_search` 以及为工作区或用户配置的任何 MCP 工具。

当您委托给自定义代理时，子代理使用该代理的 `tools`、`toolsSettings` 和 `allowedTools`。如果工具未列在自定义代理配置中，子代理将无法使用它 — 与直接运行该代理相同。

**摘要工具**

子代理还获得内置的 `summary` 工具，用于在任务完成时向主代理报告发现。这是自动包含的 — 您不需要将其添加到代理配置中。

## 运行时行为

一些运行时行为与常规聊天会话不同:

- **工作目录读取自动批准。** 当前工作目录内的 `fs_read` 不提示批准。工作目录外的读取仍会提示。
- **非交互式子代理无法提示批准。** 如果 `is_interactive` 为 false 且工具需要批准，子代理会快速失败而不是挂起。将代理添加到 `trustedAgents`，或设置 `dangerously_trust_all_tools` 以避免提示。参见[配置子代理访问](#configuring-subagent-access)。
- **子代理会话记录其父会话。** 每个持久化的子代理会话包含生成会话的 ID，因此您可以将委托任务追溯到启动它的对话。

## 子代理执行监控器

Kiro 提供专用监控器来实时跟踪子代理活动。按 Ctrl+G 打开监控器。它显示每个子代理在完成任务时的当前状态、工具调用和输出。

当子代理运行时，您可以查看其执行详情 — 包括正在读取哪些文件、执行哪些命令以及做出哪些决策 — 而不打断主对话。这在并行运行多个子代理时特别有用，因为您可以独立跟踪每个子代理并在需要时干预。

在监控器内，使用 Ctrl+D 和 Ctrl+U 在子代理之间导航，按 `q` 返回主聊天。

## 任务依赖

子代理支持将复杂任务分解为有向无环图 (DAG)，其中任务可以相互依赖。主代理预先规划完整的任务图，然后按正确顺序执行子代理 — 并行运行独立任务，在启动依赖任务之前等待依赖项完成。

例如，重构工作流可能如下:

```
  ┌─────────────┐
  │  1. 分析    │
  │   依赖关系  │
  └──────┬───────┘
         │
  ┌──────▼───────┐
  │ 2. 重构      │
  │   模块      │
  └──────┬───────┘
         │
  ┌──────▼───────┐
  │  3. 运行并   │
  │  修复测试    │
  └──────────────┘
```

步骤 2 等待步骤 1 完成。步骤 3 等待步骤 2。同级别的独立任务并行运行。

```bash
> 重构 auth 模块 — 先分析依赖关系，然后重构每个服务，最后运行测试
```

> **注意**
>
> 任务图是预先规划的，无法在执行期间修改。代理在任何子代理开始运行之前确定完整的 DAG。

## 配置子代理访问

子代理权限位于代理配置的 `toolsSettings.subagent` 下。您可以限制可以生成哪些代理、哪些无需提示即可运行，以及每个代理运行时可以做什么。

### 限制可生成的代理

使用 `availableAgents` 限制主代理可以委托给哪些代理:

```json
{
  "toolsSettings": {
    "subagent": {
      "availableAgents": ["reviewer", "tester", "docs-*"]
    }
  }
}
```

使用此配置，只有 `reviewer`、`tester` 和匹配 `docs-*` 的代理可以用作子代理。支持 glob 模式。

### 信任特定代理

使用 `trustedAgents` 允许特定代理无需权限提示即可运行:

```json
{
  "name": "orchestrator",
  "description": "协调多个专业子代理的代理",
  "tools": ["fs_read", "subagent"],
  "toolsSettings": {
    "subagent": {
      "trustedAgents": ["reviewer", "tester", "analyzer"]
    }
  }
}
```

使用此配置，编排者可以生成 `reviewer`、`tester` 和 `analyzer` 子代理，无需每次都要求用户批准。支持像 `test-*` 这样的 glob 模式。

您可以组合 `availableAgents` 和 `trustedAgents` 进行细粒度控制:

```json
{
  "toolsSettings": {
    "subagent": {
      "availableAgents": ["reviewer", "tester", "analyzer", "docs-*"],
      "trustedAgents": ["reviewer", "tester"]
    }
  }
}
```

这允许四个代理作为子代理生成，但只有 `reviewer` 和 `tester` 无需提示运行。

要限制子代理可以使用的工具，请在**子代理自己的代理配置文件**中配置 `allowedTools`，而不是在父代理中。每个生成的子代理使用自己的代理配置运行，因此工具权限在那里设置。

## 最佳实践

1. **用于复杂任务** - 对受益于隔离的多步骤操作最有价值
2. **提供清晰指令** - 具体的任务描述会产生更好的结果
3. **监控进度** - 定期检查长时间运行的子代理
4. **审查结果** - 在根据建议采取行动之前验证子代理输出

## 故障排除

| 问题 | 解决方案 |
|------|----------|
| 子代理未启动 | 验证任务描述清晰可执行 |
| 缺少工具访问权限 | 检查代理配置的 `tools` 和 `allowedTools` 字段。对于自定义代理，确保列出所需的工具。参见[工具可用性](#tool-availability)。 |
| 批准提示阻塞非交互式子代理 | 将代理添加到 `trustedAgents`，或使用 `/tools trust subagent` 信任 `subagent` 工具。参见[信任特定代理](#trusting-specific-agents)。 |
| 主代理无法生成子代理 | 对于自定义编排代理，将 `subagent` 添加到 `tools` 数组（或包含 `@builtin`）。 |
| 结果不完整 | 提供更具体的指令或分解为更小的任务 |
