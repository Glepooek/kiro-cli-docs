# 管理工具权限

您可以使用 `/tools` 命令管理 Kiro 用于在您的系统上执行操作的工具权限。这提供了对 Kiro 可以执行的操作的细粒度控制。

## 工具命令

| 命令 | 描述 |
|------|------|
| `help` | 显示工具相关帮助。 |
| `trust` | 为会话信任特定工具。 |
| `untrust` | 将工具恢复为每次请求确认。 |
| `trust-all` | 信任所有工具（等同于已弃用的 /acceptall）。 |
| `reset` | 将所有运行时权限重置为默认值，包括 shell 信任模式、文件系统路径和拒绝的工具。 |

要查看所有工具的当前权限设置:

```bash
$ kiro-cli chat
Kiro> /tools
```

这会显示所有可用工具及其当前权限状态（受信任或每次请求）的列表。

工具权限有两种可能的状态:
- *受信任*: Kiro 可以使用该工具而无需每次请求确认。
- *每次请求*: Kiro 必须在每次使用工具前请求您的确认。

要为当前会话信任或不信任特定工具:

```bash
Kiro> /tools trust read
Kiro> /tools untrust shell
```

您还可以使用 `/tools trust-all` 一次信任所有工具（等同于已弃用的 `/acceptall` 命令）:

```bash
Kiro> /tools trust-all
```

> **警告**
>
> 使用 `/tools trust-all` 存在风险。更多信息请参见[安全使用 /tools trust-all](/docs/Chat/17_security.md/#using-tools-trust-all-safely)。

> **注意**
>
> 在终端 UI 中，`--trust-all-tools` 和 `/tools trust-all` 会在授予权限前显示确认警告。您必须确认风险才能继续。

## 可用工具

Kiro 包含以下内置工具:

| 工具 | 描述 |
|------|------|
| `read` | 读取系统上的文件和目录。 |
| `write` | 创建和修改系统上的文件。 |
| `shell` | 在系统上执行 bash 命令。 |
| `aws` | 进行 AWS CLI 调用以与 AWS 服务交互。 |
| `report` | 打开浏览器向 AWS 报告聊天问题。 |

当 Kiro 尝试使用没有明确权限的工具时，它会在继续之前请求您的批准。会出现一个基于面板的下拉菜单，提供 Yes、Trust 和 No 选项。当多个工具同时需要权限时，批准会排队并逐个呈现。您可以选择允许或拒绝操作，或为会话剩余时间信任该工具。

### Shell 命令信任级别

当 Kiro 请求运行 shell 命令时，您可以选择信任的范围。您会获得一个交互式选择器，提供针对特定命令的分层选项，而不是信任整个 `shell` 工具。例如，如果 Kiro 想运行 `git pull --rebase`，您会看到这些选项:

```
按 (↑↓) 导航 (⏎) 选择范围
> 完整命令          → git pull --rebase
  部分命令          → git pull *
  基础命令          → git *
  整个工具          → *
```

从最严格到最不严格的信任层级:

| 层级 | 信任内容 | 示例模式 |
|------|----------|----------|
| 完整命令 | 完全按书面形式的确切命令 | `git pull --rebase` |
| 部分命令 | 命令及其子命令，带任何参数 | `git pull *` |
| 基础命令 | 基础命令带任何参数 | `git *` |
| 整个工具 | 所有 shell 命令 | `*` |

选择层级后，Kiro 确认信任模式（例如 `✓ 已信任: git pull --rebase`）。选择器仅显示有意义的不同层级 — 如果命令没有子命令，则跳过部分层级。对于链式命令（管道、`&&`），Kiro 为链中的每个命令生成信任模式并进行去重。

信任模式在会话期间持久化，并作为正则表达式存储在代理的 `allowedCommands` 设置中。有关 `allowedCommands` 如何工作的更多信息，请参见 [Shell 工具设置](../reference/3_built-in-tools.md/#execute-shell-commands)。

> **警告**
>
> 如果命令匹配 `deniedCommands` 模式，则无法使用细粒度信任选项。您只能允许操作一次或信任整个工具。

### 读取和写入路径信任级别

`read` 和 `write` 工具在访问当前工作目录之外的路径时也支持细粒度信任。默认情况下，两个工具对当前工作目录都是受信任的。当 Kiro 需要读取或写入该目录之外的文件时，您会获得一个带分层选项的选择器:

```
按 (↑↓) 导航 (⏎) 选择范围
> 特定路径          → ~/.config/app/settings.json
  完整目录          → ~/.config/app
  整个工具          → *
```

从最严格到最不严格的信任层级:

| 层级 | 信任内容 | 示例 |
|------|----------|------|
| 特定路径 | 仅请求的确切文件路径 | `~/.config/app/settings.json` |
| 完整目录 | 包含目录中的所有文件 | `~/.config/app` |
| 整个工具 | 所有位置的所有读取或写入操作 | `*` |

当前工作目录内的路径不会触发选择器。

## 默认信任和权限示例

每个工具都有默认信任行为。`read` 默认对当前工作目录受信任。当 Kiro 使用工具时，它会显示正在使用的信任权限。您也可以在启动 `kiro-cli chat` 会话时指定信任权限。

以下是一些何时使用不同权限级别的示例:
- *信任 read*: 当您希望 Kiro 无需确认即可读取文件时，例如在探索代码库时。
- *信任 write*: 当您正在积极处理项目并希望 Kiro 帮助您创建或修改文件时。
- *不信任 shell*: 在敏感环境中工作时，您希望在执行前审查所有命令。
- *不信任 aws*: 在使用生产 AWS 资源时防止意外更改。
