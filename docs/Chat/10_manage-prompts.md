# 管理提示

Kiro CLI 为本地提示和模型上下文协议 (MCP) 提供提供全面的提示管理能力。该系统允许您在开发工作流程中创建、编辑、组织和使用的可重用提示。

## 关于提示类型

提示系统支持三种类型的提示:
- **本地提示**: 存储在工作区的项目特定提示
- **全局提示**: 适用于所有项目的用户级提示
- **MCP 提示**: 由 MCP 服务器提供的具有增强功能的提示

## 命令

所有提示管理都通过 `/prompts` 命令及其子命令访问。

### 列出提示

```
/prompts list
```

以三列布局显示所有可用提示，展示名称、描述和来源。显示提示计数并指示哪些提示来自本地存储、全局存储或 MCP 服务器。

### 创建提示

```
/prompts create --name name [--content content]
```

在当前工作区创建新的本地提示。

**参数**

`name` (必需) : 提示名称（最多 50 个字符）

`--content content` (可选) : 直接指定内容

**行为:**
- 如果提供 `--content`，则使用指定内容创建提示
- 如果未提供内容，则打开默认编辑器进行内容创建
- 提示保存到当前工作区的 `.kiro/prompts/`

### 编辑提示

```
/prompts edit name
```

在默认编辑器中打开现有提示进行修改。

**支持的提示:**
- 本地工作区提示
- 全局用户提示
- MCP 提示（在服务器支持的情况下）

### 查看提示详情

```
/prompts details name
```

显示提示的综合信息，包括:
- 元数据和参数详情
- AI 处理前的完整提示内容
- 参数要求和示例
- 来源信息（本地、全局或 MCP 服务器）

## 使用提示

创建提示后，使用 @ 前缀在聊天中调用它们:

```
@prompt-name
```

### 文件和目录引用 (v1.26.0+)

除了提示，您还可以使用 `@` 语法在消息中直接引用文件和目录。Kiro 会自动扩展这些引用以在对话中包含内容或结构。

**基本语法:**

```bash
# 包含文件内容
> 审查 @src/auth.rs 的安全问题

# 包含目录树
> @crates/agent/ 的结构是什么？

# 带引号的路径（用于空格）
> 检查 @"my file.txt" 是否有错误

# 相对路径
> 比较 @./v1/api.rs 和 @./v2/api.rs
```

**功能:**
- **Tab 补全** - 在 `@` 后按 Tab 自动补全文件和目录路径
- **语法高亮** - 引用以紫色高亮显示以提高可见性
- **自动格式化** - 文件显示为代码块，目录显示为树形列表
- **智能优先级** - 已知提示优先于文件路径

**大小限制:**
- 文件: 最大 250KB（更大的文件会被截断并显示警告）
- 目录: 最深 3 层，每层最多 10 个项目
- 不支持二进制文件（显示错误消息）

**优先级规则:**

当您使用 `@name` 时，Kiro 按以下顺序检查:
1. **已知提示** - 如果 `@name` 匹配提示（本地、全局或 MCP），则视为提示
2. **文件** - 否则作为文件路径检查
3. **目录** - 如果不是文件，则作为目录检查

这意味着您的提示始终优先于同名文件。

**限制:**
- 不支持 glob 模式（`@*.rs` 无效）
- 不支持行范围语法（`@file.rs:10-20` 无效）
- 不支持主目录扩展（`@~` 无效）
- 不支持二进制文件
- 没有读取权限的文件显示错误

### 示例

```
@code-review
# 使用您的本地 code-review 提示

@src/auth.rs
# 包含 src/auth.rs 文件的内容

@crates/agent/
# 显示 crates/agent/ 的目录结构
```

## 向 MCP 提示传递参数

MCP 服务器提示可以接受参数来自定义其行为。基于文件的提示（本地和全局）不支持参数。

### MCP 提示参数语法

```
@server-name/prompt-name <必需参数> [可选参数]
```

使用 `/prompts details prompt-name` 查看 MCP 提示接受哪些参数。

```
# 示例: 使用带参数的 MCP 提示
@dev-tools/analyze "性能问题" "详细"
@security-tools/scan "web-app" "高严重性"
```

## 存储位置

### 本地提示（工作区特定）

- **位置**: `project/.kiro/prompts/`
- **范围**: 仅在当前项目中可用
- **优先级**: 最高（覆盖同名全局和 MCP 提示）

### 全局提示（用户级）

- **位置**: `~/.kiro/prompts/`
- **范围**: 适用于所有项目
- **优先级**: 中等（覆盖同名 MCP 提示）

### MCP 提示

- **来源**: 由配置的 MCP 服务器提供
- **范围**: 取决于服务器配置
- **优先级**: 最低（被本地和全局提示覆盖）

## 优先级系统

当多个提示具有相同名称时，系统使用以下优先级顺序:
1. **本地提示**（最高优先级）
2. **全局提示**
3. **MCP 提示**（最低优先级）

这允许您在需要时使用项目特定版本覆盖 MCP 或全局提示。

## 增强功能

### 内容预览

系统在发送给 AI 模型之前显示完整的提示内容，消除关于实际处理了什么信息的困惑。

### 改进的错误处理

- MCP 服务器错误转换为用户友好的消息
- 从提示元数据生成有用的使用示例
- 为无效参数或缺失要求提供清晰指导

### 可视化格式

- 所有提示操作的一致终端样式
- 所有提示消息类型的正确内容显示
- 改进列表可读性的三列布局

## MCP 集成

提示系统与 MCP 服务器无缝集成:
- **自动发现**: MCP 提示自动从配置的服务器发现
- **增强 UX**: 改进的 MCP 提示管理用户体验
- **错误转换**: 原始 JSON 错误转换为可操作的消息
- **内容预览**: 执行前 MCP 提示的完整内容预览

## 示例

这些示例演示基于文件的提示创建和 MCP 提示使用。

### 基于文件的提示创建和使用

```
# 创建不带参数的简单提示
/prompts create --name code-review --content "请审查此代码的最佳实践、安全问题和潜在改进："

# 使用提示（基于文件的提示不支持参数）
@code-review
```

### 带参数的 MCP 提示使用

```
# 使用带参数的 MCP 提示
@dev-tools/analyze "性能瓶颈" "cpu 使用率"
@security-tools/scan "web-app" "高严重性"
@aws-tools/deploy "my-service" "production" "us-west-2"
```
