# 规划代理

规划代理是一个专门的内置代理，帮助将想法转化为结构化的实现计划。它引导您完成需求收集、研究，并在切换到执行模式之前创建详细的任务分解。

## 入门

### 键盘快捷键

按 `Shift + Tab` 在规划和执行模式之间切换。

### 斜杠命令

```bash
> /plan

切换到 Kiro [plan] 代理。将任何想法转化为完全可工作的代码。
您今天想构建什么？

[plan] >
```

### 带即时提示

```bash
> /plan 构建用户认证的 REST API
```

激活时，您会看到:
- 提示符中的 `[plan]` 指示器
- 切换模式时的欢迎消息

## 规划工作流程

### 1. 需求收集

规划器通过结构化问题引导您细化初始想法。

```bash
[plan] > 我想构建一个待办事项应用

我理解您想构建一个待办事项应用。让我帮您规划这个实现。

**我的理解**: 您想创建一个用于管理任务的待办事项应用程序。

让我收集一些需求来创建详细的计划:

[1]: 这个待办事项应用应该针对什么平台？
a. **Web 应用** - 基于浏览器，使用 HTML/CSS/JavaScript
b. **移动应用** - 原生 iOS/Android 或跨平台
c. **桌面应用** - Electron、Tauri 或原生桌面
d. **CLI 工具** - 命令行界面
e. **其他** - 提供您自己的答案

[2]: 这个待办事项应用的主要用例是什么？
a. **个人任务管理** - 个人生产力
b. **团队协作** - 共享任务和分配
c. **项目管理** - 具有依赖关系的复杂工作流
d. **其他** - 描述您的具体需求

（使用聊天回答任意子集：例如 "1=a, 2=b" 或提供您自己的答案）
```

| 功能 | 描述 |
|------|------|
| 结构化问题 | 带有多选选项的清晰编号问题 |
| 灵活响应 | 回答单个问题或提供自定义响应 |
| 迭代过程 | 通过多轮问题建立理解 |
| 上下文感知 | 根据您的答案调整后续问题 |

### 2. 研究和分析

规划器探索您的代码库并研究相关技术。

| 能力 | 描述 |
|------|------|
| 代码探索 | 使用 code、grep 和 glob 工具理解现有代码 |
| 技术研究 | 识别相关框架、库和模式 |
| 架构分析 | 审查现有项目结构和约定 |

### 3. 实现计划

创建详细的、分步骤的实现计划，具有明确的目标。

```bash
**实现计划 - 待办事项 CLI 命令**

**问题陈述**: 为现有 Kiro CLI 添加待办事项管理以进行任务跟踪。

**需求**:
- 用于 CRUD 操作的 CLI 命令
- 本地 SQLite 存储
- 优先级和截止日期支持

**任务分解**:

任务 1: 创建数据库模式和模型
- 定义具有所需字段的 Todo 结构体
- 为 todos 表创建数据库迁移
- 演示: 可以在数据库中创建和查询 todos

任务 2: 实现 CLI 命令结构
- 添加带有 add/list/complete 操作的 todo 子命令
- 演示: CLI 接受 todo 命令并显示帮助

任务 3: 添加高级功能
- 实现截止日期和优先级排序
- 演示: 具有所有功能的完整 todo 系统
```

每个任务包括:
- **明确目标** - 具体、可衡量的目标
- **实现指导** - 总体方法和关键考虑事项
- **演示描述** - 可以演示的工作功能

### 4. 计划批准和交接

在切换到执行之前，规划器寻求您的批准。

```bash
[plan] > 这个计划看起来不错，还是您想让我调整什么？

> 这个计划很棒！让我们实现它。

*规划完成！* 准备退出 [plan] 代理开始您的实现吗？[y/n]:

> y
```

交接过程:
1. 您批准实现计划
2. 交互式提示确认切换到执行
3. 自动过渡回之前的代理
4. 完整计划传递给执行代理

## 只读设计

规划代理以只读模式运行，以保持专注于规划。

| 操作 | 状态 |
|------|------|
| 文件读取 | ✓ 完全访问以探索代码库 |
| 代码智能 | ✓ 用于理解代码结构的 LSP 操作 |
| 搜索 (grep, glob) | ✓ 代码探索 |
| Web 搜索 | ✓ 文档和研究访问 |
| 文件写入 | ✗ 无法创建或修改文件 |
| 命令执行 | ✗ 仅限于只读 bash 命令 |
| MCP 工具 | ✗ 无法使用 MCP 工具 |

## 最佳实践

1. **用于复杂任务** - 对多步骤实现最有价值
2. **参与问题** - 认真回答结构化问题
3. **让它探索** - 允许规划器分析您现有的代码库
4. **审查计划** - 确保计划在交接前符合预期
5. **按需迭代** - 继续细化直到计划清晰

## 故障排除

| 问题 | 解决方案 |
|------|----------|
| 如何退出规划代理？ | 使用 `Shift + Tab` 返回您之前的代理。 |
| 规划会话中断 | 使用 `/plan` 重新进入规划并从您中断的地方继续。 |
| 计划未传输到执行代理 | 确保在提示 "准备退出 [plan] 代理开始您的实现吗？[y/n]" 时回答 "y"。 |

## 示例工作流程

```bash
> /plan 为我的 Web 应用添加用户认证

[plan] > 我理解您想为您的 Web 应用添加用户认证。

**我的理解**: 您想为现有 Web 应用实现用户认证功能。

[1]: 您更喜欢什么认证方法？
a. **邮箱/密码** - 传统的用户名和密码
b. **OAuth** - Google、GitHub 或其他 OAuth 提供商
c. **魔法链接** - 无密码基于邮件的认证
d. **多因素** - 结合 2FA 的多种方法

> 1=a

[plan] > 太好了！使用邮箱/密码认证。

[2]: 您当前的技术栈是什么？
a. **React + Node.js** - JavaScript 全栈
b. **Next.js** - 具有服务端渲染的 React
c. **Django/Flask** - Python Web 框架
d. **其他** - 请说明

> 2=d, 我使用 Rust 和 Axum 框架

[plan] > 完美！Rust 和 Axum 是安全认证的绝佳选择。

*正在研究 Axum 认证模式...*
*正在探索您现有的代码库结构...*

**实现计划 - 用户认证系统**
[详细计划如下...]

这个计划看起来不错，还是您想让我调整什么？

> 看起来很完美！

准备退出 [plan] 代理开始您的实现吗？[y/n]: y

[default] > 实现这个计划: [计划内容已传输到执行代理]
```
