# Kiro CLI 隐私与安全文档

> 来源：https://kiro.dev/docs/cli/privacy-and-security/

Kiro 是一款 AWS 应用程序，可作为独立的智能 IDE 运行。Kiro 的安全框架建立在 AWS 的安全基础设施之上，遵循保护您的开发环境和数据的最佳实践。在 AWS，云安全是最高优先级。作为 AWS 客户，您受益于专为满足最安全敏感组织要求而构建的数据中心和网络架构。

安全是 AWS 和您之间的共同责任。[共享责任模型](https://aws.amazon.com/compliance/shared-responsibility-model/)将其描述为云本身的安全和云内部的安全：

- **云本身的安全** – AWS 负责保护在 AWS 云中运行 AWS 服务的基础设施。AWS 还为您提供可安全使用的服务。第三方审计师作为 [AWS 合规计划](https://aws.amazon.com/compliance/programs/)的一部分，定期测试和验证我们安全措施的有效性。要了解适用于 Kiro 的合规计划，请参阅 [AWS 合规计划范围内的服务](https://aws.amazon.com/compliance/services-in-scope/)。
- **云内部的安全** – 您的责任取决于您使用的 AWS 服务。您还需对其他因素负责，包括数据的敏感性、您公司的要求以及适用的法律法规。

本文档帮助您了解在使用 Kiro 时如何应用共享责任模型，向您展示如何配置 Kiro 以满足您的安全和合规目标，并帮助您了解如何使用其他 AWS 服务来监控和保护您的 Kiro 资源。

## URL 获取

在 Kiro 聊天模块中，您可以粘贴特定 URL，让设备获取并作为上下文使用，帮助 Kiro 回答您的问题或解决您的任务。您对获取的 URL 内容负责，并需确保您的使用符合适用的第三方条款和法律法规。

## Autopilot 与 Supervised 模式

Kiro 提供两种交互模式：Autopilot 和 Supervised，控制您如何审查代理操作。两种模式授予代理相同的能力：在代码库中创建、修改、搜索和删除文件，以及运行影响文件系统的命令。区别在于审查工作流，而非底层权限或访问范围。

**警告**

**Supervised 模式是代码审查工作流，而非安全控制。** 它旨在帮助您审查和批准代理生成的更改。它不充当沙箱、隔离边界或访问控制机制。要限制代理可以访问或修改的内容，请使用[受保护路径](#受保护路径)、[可信命令](#可信命令)、工作区隔离和凭证范围设置，如[最佳实践](#最佳实践)中所述。

### 模式对比

| 能力 | Autopilot | Supervised |
|------|-----------|------------|
| 代理可以读取文件 | 是 | 是 |
| 代理可以将文件写入磁盘 | 是 | 是 |
| 代理可以运行命令 | 是（遵循可信命令策略） | 是（遵循可信命令策略） |
| 应用更改前的审查步骤 | 否，更改立即应用 | 是，您审查差异并接受或拒绝 |
| 还原能力 | 手动（通过**撤销所有更改**或检查点） | 拒绝时自动还原；也可手动还原 |
| 防止未经批准写入受保护路径 | 是 | 是 |

### Supervised 模式的工作原理

在两种模式下，代理在工具执行期间将文件更改写入磁盘。在 Supervised 模式下，这些写入操作会被标记供您审查。代理回合完成后，Kiro 检查待处理的文件更改，并在继续之前提示您接受或拒绝。如果您拒绝，文件将还原到回合开始前的状态。

Kiro 将以下操作分类为文件修改操作。任何这些操作都会在代理回合结束时触发强制审查提示：

| 操作 | 描述 |
|------|------|
| 文件创建或覆盖 | 创建新文件或替换文件内容 |
| 文本替换 | 替换文件中的特定文本 |
| 内容追加 | 在文件末尾添加内容 |
| 文件删除 | 从工作区移除文件 |
| 代码编辑 | 修改文件中的代码 |
| 符号重命名 | 跨文件重命名变量、函数或类 |
| 文件重定位 | 移动文件并更新其引用 |

此审查检查内置于 Kiro 的工作流程中，AI 模型无法跳过。如果回合期间运行了文件修改操作，批准提示将会出现。

Shell 命令遵循单独的批准路径。默认情况下，所有命令在执行前都需要您的批准（参见[可信命令](#可信命令)）。要保持完全监督，请保持可信命令列表最小化，避免使用宽泛的通配符。

### Supervised 模式提供的功能

启用 Supervised 模式后，Kiro 对文件修改操作强制执行以下行为：

- **文件修改操作的回合级审查**：上述每个文件修改操作都会在应用更改前导致批准提示。
- **拒绝时自动还原**：如果您拒绝，文件将恢复到代理回合开始前的确切状态。
- **受保护路径强制执行**：在两种模式下，写入[受保护路径](#受保护路径)都需要在写入发生前获得明确批准。
- **命令批准**：在两种模式下，无法识别的命令在执行前都需要您的批准。

### 范围和限制

Supervised 模式审查通过 Kiro 文件编辑操作进行的更改。其他操作（如您已添加到可信列表中的 shell 命令）遵循其自己的批准策略。Supervised 模式不限制代理可以读取哪些文件、可以建议哪些命令或具有什么网络访问权限。

要保持对环境的完全监督：

- 保持[可信命令](#可信命令)列表最小化，避免使用宽泛的通配符。
- 使用[受保护路径](#受保护路径)要求对敏感位置的写入进行批准。
- 按照[最佳实践](#最佳实践)中所述使用工作区隔离和凭证范围设置。

### Autopilot 模式（默认）

在 Autopilot 模式下，Kiro 自主工作：

- Kiro 执行多个步骤，无需为每一步请求批准。
- Kiro 根据其对您需求的理解做出决策。
- 您可以在聊天界面中切换 autopilot 开关。
- 更改立即写入并应用。您可以在事后审查它们。
- 您可以随时中断，并通过**撤销所有更改**或[检查点](#检查点)还原更改。

### Supervised 模式

在 Supervised 模式下，Kiro 以交互方式工作，在每个回合后暂停供您审查：

- 代理修改文件后，它会暂停并呈现差异供您审查。
- 您可以接受单个更改（hunk 级别粒度）或拒绝它们以还原。
- 代理在需要时会询问澄清问题。
- 为减少中断，对同一文件的连续编辑可能会批量处理。

Supervised 模式最适合您希望仔细审查代理输出的情况。例如，在陌生的代码库中工作、对关键路径进行更改，或让新团队成员熟悉代理辅助工作流程时。

### 选择合适的模式

当您信任任务范围并希望代理高效工作而不受干扰时，使用 **Autopilot**。当您希望在更改持久化之前审查每组更改时，使用 **Supervised**。在两种情况下，都应应用[最佳实践](#最佳实践)中描述的安全控制来保护敏感文件、凭证和基础设施。

在任一模式下操作时，您可以通过在**聊天**模块中选择**查看所有更改**来查看代理进行的单个或所有文件更改。您也可以选择**撤销所有更改**或还原到[检查点](#检查点)将文件恢复到之前的状态。

## 可信命令

默认情况下，Kiro 在运行任何命令前都需要批准。您可以在设置中搜索 **Kiro Agent: Trusted Commands** 来创建自己的可信命令列表。

Kiro 使用简单的字符串前缀匹配来确定命令是否应自动受信任：

- **精确匹配**：命令必须完全匹配（例如 `npm install`）
- **通配符匹配**：使用 `*` 信任命令变体（例如 `npm *` 信任所有 npm 命令）
- **全局信任**：单独使用 `*` 信任所有命令（请极度谨慎使用）

系统将整个命令视为单个字符串，仅检查它们是否以可信模式开头。它不分析命令结构、链或特殊字符，因此您需要完全负责仔细配置可信模式。

## 受保护路径

受保护路径是一项安全功能，要求在写入指定的敏感目录或文件之前获得明确批准。这提供了一层额外的保护，防止对关键文件进行意外或未经授权的修改。

**注意**：受保护路径功能的具体配置方式和使用方法，请参考 Kiro 设置中的相关选项。

## 最佳实践

Kiro 提供了许多安全功能供您在制定和实施自己的安全策略时考虑。以下最佳实践是一般性指导原则，不代表完整的安全解决方案。由于这些最佳实践可能不适合或不充分于您的环境，请将其视为有用的参考而非规定。

### 保护您的资源

使用 GitHub 或 Google 身份验证时，请注意 Kiro 代理在您的本地环境中运行，可能访问：

- 本地文件和仓库
- 环境变量
- 环境中存储的 AWS 凭证
- 其他包含敏感信息的配置文件

### 建议

1. **工作区隔离**
   - 将敏感项目保持在单独的工作区中
   - 使用 .gitignore 防止访问敏感文件
   - 考虑使用 IDE 的工作区信任功能

2. **使用干净的环境**
   - 考虑为 Kiro 创建专用用户账户或容器环境
   - 仅限制访问当前项目所需的仓库和资源

3. **谨慎管理 AWS 凭证**
   - 使用具有适当权限的临时凭证
   - 考虑使用 AWS 命名配置文件隔离 Kiro 的访问
   - 对于敏感工作，不需要时从环境中移除 AWS 凭证

4. **仓库访问控制**
   - 使用 GitHub 身份验证时，审查 Kiro 可以访问哪些仓库
   - 尽可能使用特定于仓库的访问令牌
   - 定期审计访问权限

## 检查点

检查点功能允许您在对话过程中保存工作区的当前状态，并在需要时还原到该状态。这为 Autopilot 和 Supervised 模式都提供了额外的安全保障。

## 远程扩展安全

**警告**

**安全提示**：使用远程扩展会在本地计算机和远程计算机之间打开连接。仅连接到您信任的安全远程计算机，且该计算机由您信任的一方拥有。受损的远程设备可能利用该连接在您的本地计算机上执行代码。第三方扩展（包括远程扩展）不是由 Kiro 开发、维护或管理的。我们不对第三方扩展负责，也无法保证其稳定性、兼容性或持续支持。

Kiro 支持 Open VSX 扩展，包括远程 SSH 扩展（Open VSX 上社区维护的 [Open Remote - SSH](https://open-vsx.org/extension/jeanp413/open-remote-ssh) 扩展是热门选择），以提供熟悉的开发体验。有关 Kiro 中扩展兼容性和支持的全面信息，请参阅我们的[扩展兼容性指南](/docs/guides/migrating-from-vscode/#extension-compatibility)。

通过遵循这些做法，您可以在保持开发环境适当安全边界的同时，享受 Kiro 的强大功能。
