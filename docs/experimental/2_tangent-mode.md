# 切线模式

切线模式创建对话检查点，允许您探索副主题而不打断主对话流程。进入切线模式，提问或探索想法，然后返回到原始对话，正好从您离开的地方继续。

## 启用切线模式

切线模式是实验性的，必须启用：

**通过实验命令：**

```bash
/experiment
# 从列表中选择切线模式
```

**通过设置：**

```bash
kiro-cli settings chat.enableTangentMode true
```

## 基本用法

### 进入切线模式

使用 `/tangent` 或 **Ctrl+T**：

`> /tangent
创建了对话检查点 (↯)。使用 ctrl + t 或 /tangent 稍后恢复对话。`

### 在切线模式中

您会在提示中看到黄色的 `↯` 符号：

`↯ > async 和 sync 函数有什么区别？`

### 退出切线模式

再次使用 `/tangent` 或 **Ctrl+T**：

`↯ > /tangent
从检查点 (↯) 恢复对话。- 返回主对话。`

### 带尾部退出

使用 `/tangent tail` 保留最后的对话条目（问题 + 回答）：

`↯ > /tangent tail
从检查点 (↯) 恢复对话，保留最后的对话条目。`

## 使用示例

### 示例 1：探索替代方案

`> 我需要在 Python 中处理一个大型 CSV 文件。最好的方法是什么？

我建议使用 pandas 进行 CSV 处理...

> /tangent
创建了对话检查点 (↯)。

↯ > 使用 csv 模块而不是 pandas 怎么样？

csv 模块更轻量...

↯ > /tangent
从检查点 (↯) 恢复对话。

> 谢谢！我会用 pandas。你能展示一下错误处理吗？`

### 示例 2：获取 Kiro CLI 帮助

`> 帮我写一个部署脚本

我可以帮你创建部署脚本...

> /tangent
创建了对话检查点 (↯)。

↯ > Kiro CLI 有哪些可用的文件操作命令？

Kiro CLI 提供 read、write、shell...

↯ > /tangent
从检查点 (↯) 恢复对话。

> 这是一个用于 AWS 的 Node.js 应用程序`

### 示例 3：澄清需求

`> 我需要优化这个 SQL 查询

你能分享你想优化的查询吗？

> /tangent
创建了对话检查点 (↯)。

↯ > 你需要什么信息来帮助优化查询？

要有效优化 SQL 查询，我需要：
1. 当前的查询
2. 表结构和索引...

↯ > /tangent
从检查点 (↯) 恢复对话。

> 这是我的查询：SELECT * FROM orders...`

### 示例 4：保留有用信息

`> 帮我调试这个 Python 错误

我可以帮你调试。你能分享错误消息吗？

> /tangent
创建了对话检查点 (↯)。

↯ > 最常见的 Python 调试技术有哪些？

以下是最有效的 Python 调试技术：
1. 策略性地使用 print 语句
2. 利用 Python 调试器 (pdb)...

↯ > /tangent tail
从检查点 (↯) 恢复对话，保留最后的对话条目。

> 这是我的错误：TypeError: unsupported operand type(s)...

# 保留的关于调试技术的条目现在成为主对话的一部分`

## 配置

### 键盘快捷键

更改快捷键（默认：t）：

```bash
kiro-cli settings chat.tangentModeKey y
```

### introspect 的自动切线

为 Kiro CLI 帮助问题自动进入切线模式：

```bash
kiro-cli settings introspect.tangentMode true
```

## 视觉指示器

- **普通模式**：`> `（品红色）
- **切线模式**：`↯ > `（黄色 ↯ + 品红色）
- **带代理**：`[dev] ↯ > `（青色 + 黄色 ↯ + 品红色）

## 何时使用切线模式

### 好的用例

- **询问澄清性问题**关于当前主题
- **探索替代方案**在决定之前
- **获取帮助**关于 Kiro CLI 命令或功能
- **测试理解**概念
- **快速副问题**不需要在主上下文中

### 何时不使用

- **完全无关的主题** - 开始新的对话
- **长时间、复杂的讨论** - 使用常规对话流程
- **当你想要副讨论在主上下文中时** - 不要使用切线模式

## 提示

1. **保持切线专注**：简短探索，不要长时间讨论
2. **及时返回**：不要忘记你在切线模式中
3. **用于澄清**：非常适合"等等，X 是什么意思？"的问题
4. **安全实验**：测试想法而不影响主对话
5. **使用 `/tangent tail`**：当切线问题和答案对主对话都有用时

## 工作原理

### 检查点创建

当您进入切线模式时：
1. 当前对话状态保存为检查点
2. 您可以在切线模式中继续对话
3. 所有切线对话与主线程分离

### 恢复

当您退出切线模式时：
1. 对话返回到检查点状态
2. 切线对话被丢弃（除非使用 `tail`）
3. 主对话继续，就像切线从未发生过一样

### 尾部模式

使用 `/tangent tail`：
1. 像正常退出一样返回检查点
2. 保留切线中的最后一对问答
3. 将该问答添加到主对话上下文
4. 当切线提供了有价值的信息时很有用

## 限制

- **切线对话被丢弃**当您退出时（除非使用 tail）
- **只支持一级切线**（没有嵌套切线）
- **实验性功能**可能更改或移除
- **必须显式启用**使用前

## 故障排除

### 切线模式不起作用

通过实验启用：

```bash
/experiment
# 从列表中选择切线模式
```

或通过设置启用：

```bash
kiro-cli settings chat.enableTangentMode true
```

### 键盘快捷键不起作用

检查或重置快捷键：

```bash
kiro-cli settings chat.tangentModeKey t
```

确保您使用的是 Ctrl+T（不仅仅是 T）。

### 在切线模式中迷失

在提示中寻找 `↯` 符号。使用 `/tangent` 退出并返回主对话。

### 意外丢弃重要信息

如果在没有使用 `tail` 的情况下退出切线模式并丢失重要信息：
1. 遗憾的是，切线对话无法恢复
2. 您需要在主对话中重新提问
3. 以后考虑使用 `/tangent tail` 来保留重要的问答对

## 相关功能

- **Introspect**: Kiro CLI 帮助（如果配置则自动进入切线模式）
- **实验功能**: 使用 `/experiment` 管理实验性功能
- **检查点**: 类似概念但用于文件更改

## 最佳实践

### 工作流集成

1. **开始主任务**：开始您的主要对话
2. **进入切线**：当出现副问题时，使用 `/tangent`
3. **自由探索**：不用担心地询问澄清性问题
4. **决定是否尾部**：如果切线有用，使用 `/tangent tail`
5. **继续主任务**：返回您的主要任务

### 示例工作流

```
> 帮我重构这个 React 组件

# 主对话开始...

> /tangent
↯ > useMemo 和 useCallback 有什么区别？

# 获取澄清...

↯ > /tangent tail  # 这很有用，保留它

> 现在我明白了。让我用 useMemo 来处理昂贵的计算...
```
