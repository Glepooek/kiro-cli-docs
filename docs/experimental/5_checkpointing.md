# 检查点

检查点启用会话范围的快照，使用类似 Git 的命令跟踪文件更改。此功能创建一个影子裸 git 仓库来管理聊天会话中的文件状态。

## 概述

检查点为您的聊天会话提供版本控制，允许您：
- 在任何时刻创建文件更改快照
- 比较文件的不同状态
- 恢复到以前的检查点
- 跟踪每次对话中发生了什么变化

## 启用检查点

```bash
kiro-cli settings chat.enableCheckpoint true
```

或使用实验命令：

```bash
/experiment
# 从列表中选择 "Checkpointing"
```

## 工作原理

### 自动初始化

- **在 git 仓库中**：当您开始聊天会话时自动启用
- **非 git 目录**：需要用 `/checkpoint init` 手动初始化
- **会话范围**：会话结束时影子仓库会被清理

### 影子仓库

检查点创建一个临时裸 git 仓库，它：
- 跟踪文件更改而不影响您的实际 git 仓库
- 为每次对话存储快照
- 允许比较和恢复文件状态
- 会话结束时自动清理

## 命令

### /checkpoint init

手动启用检查点（如果不在 git 仓库中则需要）：

```bash
/checkpoint init
```

### /checkpoint list

显示回合级别的检查点及文件统计：

```bash
/checkpoint list [--limit N]
```

**示例输出：**

`[0] 2025-09-18 14:00:00 - 初始检查点
[1] 2025-09-18 14:05:31 - 添加 two_sum.py (+1 文件)
[2] 2025-09-18 14:07:10 - 添加测试 (修改 1)
[3] 2025-09-18 14:10:45 - 重构算法 (修改 1)
`

### /checkpoint expand

显示特定回合下的工具级别检查点：

```bash
/checkpoint expand <tag>
```

**示例：**

`> /checkpoint expand 2

[2] 2025-09-18 14:07:10 - 添加测试
 └─ [2.1] write: 为 two_sum.py 添加最小测试用例 (修改 1)
`

### /checkpoint diff

比较检查点或与当前状态比较：

```bash
/checkpoint diff <tag1> [tag2|HEAD]
```

**示例：**

```bash
/checkpoint diff 1 2        # 比较检查点 1 和检查点 2
/checkpoint diff 1 HEAD     # 比较检查点 1 和当前状态
/checkpoint diff 1          # 同上（HEAD 是默认值）
```

### /checkpoint restore

恢复到检查点：

```bash
/checkpoint restore [<tag>] [--hard]
```

**交互式选择器**：如果未指定标签，显示交互式选择

**恢复选项：**
- **默认**：恢复跟踪的更改和删除；保留检查点后创建的文件
- **`--hard`**：使工作区完全匹配检查点；删除检查点后创建的跟踪文件

**示例：**

```bash
/checkpoint restore 2       # 恢复到检查点 2（软）
/checkpoint restore 2 --hard # 恢复到检查点 2（硬）
/checkpoint restore         # 交互式选择
```

### /checkpoint clean

删除会话影子仓库：

```bash
/checkpoint clean
```

**警告**：这会删除当前会话的所有检查点数据。

## 恢复模式

### 默认恢复（软）

恢复跟踪的更改和删除但保留新文件：

```bash
/checkpoint restore 2
```

**发生什么：**
- 修改的文件恢复到检查点状态
- 删除的文件被恢复
- 检查点后创建的文件被保留

**何时使用：**
- 您想撤销更改但保留新工作
- 测试不同方法
- 恢复特定修改

### 硬恢复

使工作区完全匹配检查点状态：

```bash
/checkpoint restore 2 --hard
```

**发生什么：**
- 修改的文件恢复到检查点状态
- 删除的文件被恢复
- 检查点后创建的文件被删除

**何时使用：**
- 您想要精确的检查点状态
- 完全放弃最近的工作
- 从已知的良好状态重新开始

**⚠️ 警告**：硬恢复会永久删除文件。谨慎使用。

## 用例

### 实验更改

`> 帮我重构这个函数

# Kiro 进行更改...

> /checkpoint list
[0] 初始检查点
[1] 重构函数 (修改 1)

> 实际上，让我们尝试不同的方法

> /checkpoint restore 0
# 回到原始状态

> 现在尝试使用不同的模式...
`

### 比较方法

`> 实现功能 A

# 实现完成

> /checkpoint list
[1] 实现功能 A (修改 2)

> 现在给我看一个替代实现

# 替代实现

> /checkpoint list
[2] 替代实现 (修改 2)

> /checkpoint diff 1 2
# 查看方法之间的差异
`

### 跟踪进度

`> /checkpoint list
[0] 初始状态
[1] 添加用户模型 (+1 文件)
[2] 添加认证 (+2 文件)
[3] 添加测试 (修改 3)

> /checkpoint expand 2
[2] 添加认证
 └─ [2.1] write: 创建 auth.py (+1 文件)
 └─ [2.2] write: 更新 routes.py (修改 1)
`

### 从错误中恢复

`> /checkpoint list
[0] 工作代码
[1] 尝试优化 (修改 1)
[2] 更多更改 (修改 2)

# 意识到优化破坏了东西

> /checkpoint restore 0
# 回到工作状态
`

## 对话历史

当您恢复到检查点时，对话历史也会回退到那个点。这意味着：
- 检查点后的消息被删除
- 上下文返回到检查点状态
- Kiro 的理解重置到那个点

这确保了文件状态和对话上下文之间的一致性。

## 最佳实践

### 何时使用检查点

- **实验性更改**：安全地尝试不同方法
- **复杂重构**：跟踪重大更改的每一步
- **学习**：比较不同的实现
- **调试**：隔离问题何时引入

### 检查点管理

- **定期查看检查点**：使用 `/checkpoint list` 查看进度
- **使用描述性更改**：Kiro 的检查点消息帮助识别状态
- **完成后清理**：使用 `/checkpoint clean` 删除会话数据
- **对 --hard 谨慎**：只有在确定时才使用

### 工作流集成

1. **在会话开始时启用**：为复杂工作启用
2. **检查进度**：定期使用 `/checkpoint list`
3. **比较方法**：使用 `/checkpoint diff` 查看更改
4. **需要时恢复**：回到已知的良好状态
5. **清理**：会话结束时删除影子仓库

## 限制

### 会话范围

- 检查点仅存在于当前会话
- 会话结束时影子仓库被清理
- 无法跨会话共享检查点

### 文件跟踪

- 只跟踪会话期间修改的文件
- 不跟踪工作目录外的文件
- 二进制文件被跟踪但差异可能没有用

### 性能

- 大文件可能会减慢检查点操作
- 许多检查点可能消耗磁盘空间
- 大更改的差异操作可能很慢

## 故障排除

### 检查点不起作用

1. **验证已启用**：
   
   ```bash
   kiro-cli settings chat.enableCheckpoint
   ```
2. **手动初始化**（如果不在 git 仓库中）：
   
   ```bash
   /checkpoint init
   ```
3. **检查错误**：在聊天中查找错误消息

### 无法恢复检查点

1. **验证检查点存在**：
   
   ```bash
   /checkpoint list
   ```
2. **检查文件权限**：确保对文件有写访问权
3. **先尝试软恢复**：在 `--hard` 之前使用默认恢复

### 影子仓库问题

如果影子仓库损坏：
1. **清理并重新初始化**：
   
   ```bash
   /checkpoint clean
   /checkpoint init
   ```
2. **重启会话**：开始新的聊天会话

## 重要提示

⚠️ **检查点创建临时 git 仓库**，会话结束时被清理。

⚠️ **对 `--hard` 恢复要谨慎**，因为它会永久删除文件。

⚠️ **检查点是会话范围的**，不会跨会话持久化。

⚠️ **恢复时对话历史会回退**以保持一致性。
